Aven
사람이 승인하는 AI 폰 비서

안드로이드 AccessibilityService와 LLM 기반 Intent 파싱 서버를 연결해, 공식 API가 없는 배달 · 예약 · 쇼핑 앱의 화면 조작을 대신해 주는 서비스입니다. 모든 실행은 사용자가 승인 카드의 [실행]을 직접 눌러야만 시작됩니다.

01.프로젝트 개요

배달 · 예약 · 쇼핑처럼 공식 API가 없는 앱은 다른 프로그램이 대신 조작하기 어렵습니다. Aven은 접근성 API로 화면 구조를 읽고, AI 서버가 사용자의 말을 목표 · 대상 앱 · 멈추는 조건으로 바꾼 뒤, 승인받은 범위 안에서만 화면을 한 단계씩 확인하며 진행합니다. 스파이웨어나 자동 매크로로 쓰이지 않도록 HITL 보안 구조를 기본으로 설계했고, Google Play 정책과 정보통신망법 · 개인정보보호법을 기준으로 검토하고 있습니다.

02.핵심 보안 원칙

  • 1 백그라운드 자율 제어 금지 No Autonomous Background

    앱이 스스로 판단해 뒤에서 움직이지 않습니다. 사용자가 음성 · 텍스트로 명령한 순간에만 한 번 활성화됩니다.

    대기 중 이벤트 수신 0 · 명령 중에만 동작
  • 2 사람의 최종 승인 Human-In-The-Loop

    조작 전에 목표와 멈추는 조건을 승인 카드로 보여 주고, 사용자가 [실행]을 직접 눌러야 시작합니다. 지점 · 옵션 선택은 사용자에게 묻습니다.

    실제 터치로만 승인 · 화면이 바뀌면 카드 무효화
  • 3 실시간 시각 피드백 Visual Overlay

    대신 누르는 위치에 포인터와 반투명 하이라이트를 표시해, 사용자가 진행 과정을 그대로 볼 수 있습니다.

    화면 터치 한 번으로 긴급 중단
  • 4 민감 동작 이중 차단 Sensitive Guard

    결제 · 비밀번호 · 계정 변경 · 금융 앱은 대리 실행 대상에서 제외합니다. 서버와 앱이 같은 규칙으로 두 번 검사합니다.

    결제 직전 정지 · 금융 앱 거부

// 왜 Kotlin인가 — 안드로이드 앱 · 백엔드 공통 언어

  • K 안드로이드 공식 우선 언어 Kotlin-first

    Google은 2019년부터 안드로이드를 Kotlin 우선으로 개발합니다. 새 Jetpack 라이브러리, 공식 문서, 예제가 Kotlin으로 먼저 나옵니다.

    자료 · 라이브러리 · 지원이 가장 많음
  • N 접근성 서비스는 네이티브로 Native OS API

    AccessibilityService와 오버레이는 안드로이드 OS API입니다. Flutter · React Native도 이 부분은 결국 네이티브로 따로 짜야 하고, 브리지를 거쳐 느려집니다.

    중간 계층 없이 화면을 읽고 바로 누름
  • ? Null 안전성 Null Safety

    화면 요소는 화면이 바뀌면 언제든 없어질(null) 수 있습니다. Kotlin은 이를 처리하지 않으면 컴파일 단계에서 막아, "없는 버튼은 누르지 않는다"는 원칙을 지키기 쉽습니다.

    button?.click() ?: stop()
  • ⟳ 코루틴 · sealed class Coroutines

    서버 응답 대기 → 화면 변화 대기 → 5초 넘으면 중단을 콜백 없이 순서대로 씁니다. 서버 응답 종류는 sealed class로 묶어 하나라도 빠뜨리면 컴파일 오류가 납니다.

    withTimeoutOrNull(5_000) { … }

백엔드도 Kotlin + Spring Boot로 만들어 앱과 서버를 한 언어로 개발합니다. Java와 100% 호환되어 Spring · JPA를 그대로 씁니다. 자세히 보기 →
