# 🛠️ Aven Android 전체 개발 스택 & 환경 정리

## 1. 기본 개발 정보

- **개발 방법론:** 애자일(Agile) 방법론 (스프린트 단위 반복 개발)
- **배포 대상:** 안드로이드 사용자, 빌드 둘
  - **play 빌드:** Google Play Store (정해진 레시피로만 실행)
  - **galaxy 빌드:** 갤럭시 스토어 (허락받은 앱에서만 AI가 단계 판단)
- **운영체제/기기 대상:** Android OS (Kotlin 클라이언트 앱). 음성 인식과 화면 판단은 서버에서 처리 (온디바이스 처리 아님)

## 2. 레이어별 기술 스택 (Tech Stack)

### ① 안드로이드 클라이언트 (Android Client)

- **언어:** Kotlin
- **UI:** Android View (Jetpack Compose 미사용, 메모리와 시작 속도 때문)
- **핵심 API:** AccessibilityService (화면 UI 노드 탐색 및 대리 클릭)
- **화면 제어 피드백:** WindowManager Overlay (실시간 터치 포인터, 하이라이트 박스, 승인 카드 표시)
- **네트워크 통신:** OkHttp (WebSocket은 AI 서버, REST API는 백엔드)
- **비동기 처리:** Kotlin Coroutines

### ② AI Engine & 음성 처리 (Python Server)

- **언어:** Python
- **웹 프레임워크:** FastAPI (Async WebSocket 및 외부 AI API 연동 최적화)
- **STT (음성 인식):** OpenAI Whisper API (서버에서 처리)
- **다음 동작 결정:** 앱별 레시피(정해진 순서) 우선, galaxy 빌드의 허락받은 앱만 LLM이 판단. 화면마다 다음 동작 1개만 결정
- **LLM (대화 답변, galaxy 빌드 단계 판단):**
  - 개발 단계 (로컬): 내 컴퓨터에서 동작하는 LLM (Ollama: exaone3.5, qwen2.5)
  - 운영 단계 (배포): 클라우드 LLM API, 이후 수집 데이터로 튜닝한 모델
- **TTS (음성 합성):** Typecast API (기본 여성·남성 목소리 각 1개, 사용자가 변경 가능). 현재 개발 중에는 기기 내장 TTS 사용

### ③ 메인 백엔드 & 데이터베이스 (Backend & DB)

- **언어/프레임워크:** Kotlin + Spring Boot (AI 서버 FastAPI와 분리 운영)
- **DB:** PostgreSQL
  - **JSONB:** 작업 기록(단계 설명, 작업 오류) 및 사용자 설정 저장
  - **Row Level Security (RLS):** 사용자 간 데이터 엄격 격리
  - **Soft Delete:** `is_deleted` 기반 안전 삭제 (지운 기록은 30일 뒤 완전 삭제)
  - **Audit Trigger:** 수정 및 접근 감사 로그 자동 기록

## 3. 개발/배포 환경 및 개발 도구 (DevOps & Tools)

### ① 로컬 개발 단계 (내 컴퓨터)

- **로컬 서버:** Python FastAPI (STT/LLM/TTS 파이프라인 처리)
- **폰 연결:** USB `adb reverse`
  - 이유: 안드로이드 실기기(스마트폰)에서 로컬 내 컴퓨터 서버로 WebSocket 통신을 연결하기 위함

### ② 배포 및 운영 단계

- **컨테이너화:** Docker & Docker Compose
- **클라우드 인프라:** GCP / AWS / Oracle Cloud 중 선택

### ③ 프로젝트 관리

- **형상 관리:** Git / GitHub
- **이슈 및 이슈 트래킹:** GitHub Projects 또는 Jira (스프린트 백로그 관리)

## 4. 시스템 전체 데이터 흐름 (Architecture Flow)

1. **[사용자]** 음성/텍스트 입력 ("OO 앱에서 장바구니 담아줘")
2. **[Android]** 음성(또는 텍스트)을 Python AI 서버로 WebSocket 전송. 이때 화면 내용은 보내지 않음
3. **[Python AI]** STT(OpenAI Whisper)로 텍스트 변환 후 판단. 일반 대화면 바로 답변하고 끝. 앱에서 할 일이면 목표 요약을 만듦
4. **[Android]** 화면에 HITL 승인 카드(목표 요약) 출력
5. **[사용자]** [실행] 버튼 직접 터치 (목표 승인)
6. **[Android ↔ Python AI]** 승인 후에만 화면 구조를 단계마다 전송 → 서버가 다음 동작 1개 결정(레시피 우선) → 화면 구조 즉시 폐기 → AccessibilityService가 Visual Overlay와 함께 수행. 결제 직전, 추가 질문, 앱 이탈, 사용자 터치 시 그 자리에서 멈추고 사용자에게 넘김
7. **[Spring Boot/PostgreSQL]** 작업 기록(단계 설명·오류)을 JSONB 형태 및 Audit Log로 기록
