# 보안 및 데이터 감사 정책 (Security & Audit Policy)

> 본 문서는 시스템 내 사용자 데이터의 안전성 확보 및 무단 데이터 접근 방지를 위한 기술적·관리적 보호 조치를 설명합니다.

[← 문서 목록으로](../../README.md)

---

## 1. 데이터베이스 격리 (Row Level Security; RLS)

- PostgreSQL의 **Row Level Security(RLS)** 를 적용하여 각 사용자별 데이터 접근 권한을 철저히 격리합니다.
- 다른 사용자의 작업 내역, Intent 메타데이터, 개인 설정에 대한 인가되지 않은 접근을 **DB 레이어에서 원천 차단**합니다.

## 2. 데이터 저장 구조 및 JSONB 메타데이터

- 작업 명령 및 실행 정보는 유연한 확장성을 가진 **JSONB** 구조로 저장됩니다.
- 주민등록번호, 카드번호, 계좌번호 등 민감 개인정보는 저장 대상에서 **전면 제외**됩니다.
- 화면 UI 구조는 Action Plan 생성 후 즉시 폐기하며, DB·로그에 기록하지 않습니다.

### 휴대폰 번호 암호화 (Field-Level Encryption)

| 컬럼 | 방식 | 용도 |
| --- | --- | --- |
| `phone_encrypted` | **AES-256-GCM** 암호화 | SMS 발송 등 원래 번호가 필요한 경우 복호화 |
| `phone_hmac` | **HMAC-SHA256** (블라인드 인덱스) | 중복 가입 확인용 검색 (암호문은 매번 달라 검색이 불가능하므로 별도 컬럼 사용) |

- 암호화 키와 HMAC 키는 서로 다른 키를 사용하며, DB와 분리된 저장소(클라우드 KMS 또는 환경 변수)에 보관합니다.
- 복호화는 SMS 발송 등 꼭 필요한 서버 코드에서만 수행하며, 로그에 번호를 출력하지 않습니다.

## 3. 데이터 삭제 정책 (Soft Delete)

- 사용자의 데이터 삭제 요청 시 즉시 물리적 삭제를 수행하지 않고 `is_deleted = true` 형태의 **Soft Delete**를 적용합니다.
- 이를 통해 법적 분쟁 및 오작동 발생 시 보안 감사를 위한 최소한의 데이터 이력을 안전하게 관리합니다.
- Soft Delete한 기록은 **30일 뒤 물리 삭제**합니다 (DB 함수 `purge_deleted_tasks`, 매일 03:30).

### 인증 정보 보호

- 단말기의 로그인 토큰은 Android Keystore의 AES-256-GCM 키로 암호화해 저장합니다.
- 토큰은 7일간 유효하지만, AI 서버는 연결할 때마다 백엔드에 계정의 현재 상태를 확인해 비활성화·탈퇴 계정을 거부합니다 (활성 확인 결과만 60초 기억).

### 계정 탈퇴 시 익명화 (Anonymization on Withdrawal)

- 탈퇴 시 사용자 계정 행의 식별 정보(이메일, 인증 정보 등)는 **물리적으로 삭제**합니다.
- 작업 기록·감사 로그의 `user_id`는 무작위 익명 식별값(예: UUID v4)으로 교체하며, 기존 ID와의 **매핑 테이블을 남기지 않습니다**.
- 명령·답변 텍스트와 실행 단계 설명은 **삭제**하고, 통계 항목(상태, 시각, 실행 방식, 단계 수, 오류 종류)만 남깁니다. 정규식 마스킹은 표시 없는 이름 등을 놓칠 수 있어 쓰지 않습니다.
- AI 답변 신고와 음성 녹음은 함께 삭제합니다.
- 익명화는 단일 트랜잭션으로 처리하여 일부만 익명화된 상태가 남지 않도록 합니다.

### 재가입 제한 해시 (Re-signup Block Hash)

- 탈퇴 시 휴대폰 번호는 **HMAC-SHA256**(서버 비밀 키 사용)으로 변환하여 별도 테이블에 저장합니다.
  - 휴대폰 번호는 경우의 수가 적어 단순 SHA-256은 전수 대입으로 복원될 수 있으므로, 비밀 키 없이는 계산할 수 없는 HMAC을 사용합니다.
  - 비밀 키는 DB와 분리된 저장소(환경 변수 또는 클라우드 KMS)에 보관합니다.
- 해시 테이블에는 해시값과 만료일만 저장하며, 익명 식별값 등 작업 기록과 연결되는 컬럼을 두지 않습니다.
- 만료일(탈퇴 후 30일)이 지난 행은 스케줄러가 매일 **물리적으로 삭제**합니다.

## 3-1. SMS 인증 보호 조치

| 항목 | 기준 |
| --- | --- |
| 인증번호 | 6자리 숫자, 유효 시간 3분, 1회 사용 후 폐기 |
| 입력 시도 제한 | 인증번호당 5회 실패 시 무효화 |
| 발송 제한 | 동일 번호 기준 1분 1회, 하루 5회 |
| 저장 | 인증번호는 평문으로 저장하지 않고 만료 후 삭제 |

## 4. 자동 감사 로깅 (Automated Audit Logging)

- 데이터 생성, 수정, 삭제 발생 시 **DB Trigger**를 통해 `updated_at` 및 감사 트레이스가 자동 기록됩니다.
- 비정상적인 대량 요청 또는 시스템 남용 시도를 실시간으로 감지할 수 있도록 모니터링 체계를 갖춥니다.

## 5. 개인 저장 공간 보호 (Personal Storage)

음성 녹음, 대화 목록, 작업 오류 기록을 보관하는 이용자별 저장 공간에 대한 보호 조치입니다.

| 항목 | 기준 |
| --- | --- |
| 저장소 | 오브젝트 스토리지(국내 리전), 공개 접근 차단 |
| 암호화 | 저장 시 서버 측 암호화 (SSE-KMS 등) |
| 격리 | 이용자별 경로 분리, 서버가 요청자와 파일 소유자 일치 여부 확인 |
| 파일 접근 | 유효 시간 5분 이하의 서명된 URL로만 제공 |
| 용량 제한 | 음성 녹음 1인당 500MB, **서버에서** 업로드 전 사용량 확인 (앱 측 확인만으로는 우회 가능) |
| 삭제 | 이용자 삭제·초기화·탈퇴 시 음성 파일은 물리 삭제, 버전 관리 기능 사용 시 이전 버전까지 삭제 |
