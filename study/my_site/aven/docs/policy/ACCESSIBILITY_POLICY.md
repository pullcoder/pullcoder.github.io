# 접근성 서비스 API 사용 정책 (Accessibility API Policy)

> 본 문서는 Google Play Developer Policy 규정에 따라 **Aven** 가 안드로이드 AccessibilityService API를 사용하는 목적과 통제 방식을 정의합니다.

---

## 1. 접근성 API 사용 목적 (Purpose of API Usage)

본 앱은 장애인 보조 도구(`isAccessibilityTool=true`)가 **아니며**, 일반 사용자의 명시적 지시에 기반한 작업 자동화 보조 도구로 동작합니다.

| 용도 | 설명 |
| --- | --- |
| **UI Element Inspection** | 사용자가 승인한 명령을 수행하는 동안에만, 대상 앱 화면의 UI 구조를 단계마다 읽습니다. |
| **User-Delegated Automation** | 사용자가 승인한 목표 안에서, **회사가 앱별로 미리 작성한 실행 순서(레시피)** 에 따라 화면 요소를 누르거나 글자를 입력·스크롤합니다. |

### Google Play 정책과의 관계

Google Play는 접근성 API를 "스스로 동작을 시작·계획·실행하는 앱"에 쓰는 것을 금지하고, 사람이 정한 고정 스크립트에 따르는 결정적 자동화는 허용합니다 ([정책](https://support.google.com/googleplay/android-developer/answer/10964491)).

| 빌드 | 다음 동작을 정하는 방법 |
| --- | --- |
| **play** (Google Play) | 레시피만. 같은 목표·화면이면 항상 같은 동작. 레시피에 없는 화면이면 멈춤. LLM은 대화 답변에만 쓰고 화면 동작을 정하지 않음 |
| **galaxy** (갤럭시 스토어) | 레시피 우선, 레시피가 없는 화면은 **회사가 허용한 앱 목록 안에서만** AI 판단 (2026-10-14 결정, 구현 예정 — 출시 전 필수) |

- 레시피는 서버에 있으며 앱 심사 후에도 갱신됩니다. Play 접근성 신고서와 시연 영상에 이 사실을 밝힙니다.
- 레시피는 자동화 근거(제휴·허락·약관 검토)가 있는 앱만 작성합니다 ([규제 보고서 1장](REGULATORY_COMPLIANCE.md)).

## 2. 4대 핵심 정책 준수 원칙 (Core Compliance Rules)

### (1) 백그라운드 자율 제어 전면 금지 (No Autonomous Background Execution)

- 앱이 스스로 판단하여 백그라운드에서 화면을 제어하거나 스파이웨어 형태로 감시하는 행위를 **전면 금지**합니다.
- 오직 사용자가 앱을 실행하여 직접 명령을 내린 시점에만 활성화됩니다.

### (2) 전면 공개 및 명시적 동의 (Prominent Disclosure)

- 앱 최초 실행 시, 접근성 권한이 필요한 이유와 처리되는 데이터 범위(화면 구조를 서버로 보내 처리 직후 폐기, 기록에 남는 단계 설명, galaxy 빌드의 외부 AI 전송 가능성), 앱 접근권한(필수·선택), 생성형 AI 사용 사실을 설명하는 전면 화면을 표시합니다.
- 동의 후에도 **설정 → 접근성 권한 안내 다시 보기**로 언제든 다시 볼 수 있고, 같은 화면에서 접근성 권한을 끌 수 있는 설정으로 이동할 수 있습니다.
- [개인정보 처리방침](PRIVACY_POLICY.md) 링크를 제공하고, 사용자의 명시적 **[동의]** 버튼 터치 후에만 안드로이드 시스템 접근성 설정 화면으로 유도합니다.

### (3) Human-In-The-Loop (HITL) 사용자 최종 승인

- AI는 화면을 자율적으로 즉시 제어하지 않습니다.
- 사용자의 명령(목표), 대상 앱, 멈추는 조건을 화면 상의 **[승인 UI 카드]** 로 먼저 제시하며, 사용자가 **[실행]** 버튼을 직접 누른 시점에만 대상 앱 화면을 읽고 대리 조작을 시작합니다 (승인 전에는 화면을 읽지 않음).
- 승인 후에는 **승인한 목표의 범위 안에서만** 화면을 한 단계씩 확인하며 진행하고, 지금 하는 단계와 누르는 위치를 실시간으로 표시합니다.
- 가게 지점·필수 옵션처럼 사용자가 정해야 하는 선택은 대신 정하지 않고 카드로 묻습니다.
- 결제·주문 확정·송금 단계 직전, 최대 단계 수(20) 초과, 대상 앱 이탈, 화면 터치 시 즉시 멈춥니다.
- 로그인·비밀번호 입력 화면에서는 화면을 읽지 않고 대리 입력도 하지 않으며, 사용자가 직접 입력한 뒤 [계속]을 누를 때까지 기다립니다.
- 금융, 결제, 계정 변경 등 **민감한 동작**과 메신저·메일·사진·연락처처럼 **다른 사람의 개인정보가 나오는 앱**은 대리 실행 대상에서 제외됩니다.

### (4) 실시간 시각적 피드백 (Visual Overlay)

- Accessibility API를 통한 화면 제어 시, 터치 포인터 및 하이라이트 박스를 레이어 화면에 실시간 표시하여 사용자가 모든 동작 과정을 인지할 수 있도록 합니다.
