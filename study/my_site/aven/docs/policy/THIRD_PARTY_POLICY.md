# 제3자 서비스 상호작용 방침 (Third-Party Interaction Policy)

> 본 문서는 AI 에이전트가 제3자 앱과 상호작용할 때 지켜야 하는 접근 범위와 제한 사항을 정의합니다.

---

## 0. 지원 앱 선정

- 대리 실행은 **자동화 근거가 있는 앱**(제휴 계약, 서면 허락, 또는 약관 검토 결과 자동화 금지 조항이 없는 앱)에만 제공합니다. 근거와 확인일은 레시피의 `terms` 항목에 기록하며, 근거가 없으면 레시피를 불러오지 않습니다.
- 대상 앱 약관이 바뀌면 다시 검토하고, 자동화를 금지하면 지원을 중단합니다.
- 레시피는 확인한 대상 앱 버전 범위(`versions`)에서만 동작하고, 앱이 업데이트되어 범위를 벗어나면 멈춥니다.

## 1. 제3자 앱 UI 접근 범위 제한

- AI 에이전트는 사용자가 요청한 목적 달성에 필요한 **최소한의 화면 요소**(메뉴 선택, 장바구니 담기, 입력 폼 작성 등)만 탐색합니다.
- 개인 메시지함, 금융 앱, 개인 설정 화면 등 요청과 무관한 앱 영역으로는 진입하지 않습니다.
- 화면 요소를 지정해 누르는 것이 기본입니다. 버튼(요소)이 없는 화면(기차 좌석 지도 등)에 한해 **좌표 터치**를 도입할 예정이며, 이때도 누르는 위치를 포인터로 표시합니다.
- 이용자가 시키지 않은 삭제·비우기·취소 버튼(예: 장바구니 비우기, 다른 가게 메뉴를 지우고 담기)은 누르지 않고 멈춥니다. 선택을 묻는 확인 창은 대신 정하지 않습니다.
- 실제로 이루어졌는지 확인하지 못한 결과는 '완료'로 알리지 않습니다. AI가 판단한 결과는 이용자에게 직접 확인하도록 안내합니다.

## 2. 제어 속도 및 과도한 요청 차단 (Rate Limiting)

- 사용자에게 최대한 빠르게 결과를 제공하기 위해 UI 제어 간격은 **100ms~500ms** 범위에서 운용합니다.
- 고정된 시간을 기다리지 않고, 다음 대상 UI 요소가 화면에 나타나는 즉시 다음 동작을 수행합니다. 단, 연속 동작 사이에는 **최소 100ms** 간격을 유지하여 클릭 연타를 방지합니다.
- 화면 로딩이 지연되어 대상 요소가 나타나지 않으면 추정 클릭을 하지 않고 대기하며, 일정 시간(예: 5초) 내에 나타나지 않으면 제어를 중단하고 이용자에게 안내합니다.

## 3. 결제 및 민감 행위 격리 (Payment Isolation)

- AI 에이전트는 결제 수단 선택 및 결제 승인 버튼을 **절대로 대리 클릭하지 않습니다**.
- 저장된 결제수단으로 한 번에 결제되는 버튼("15,000원 주문하기", "바로구매", "예약 확정" 등)도 결제 버튼으로 보고 누르지 않습니다. 앱마다 다른 확정 버튼은 레시피의 `stop_before`에 적습니다.
- 결제 직전 단계(주문 확인 화면)까지만 안내한 후 제어권을 완전히 종료하여 이용자가 직접 결제를 진행하도록 유도합니다.

## 4. 오동작 방지 및 즉시 중단 (Emergency Stop)

- AI가 화면 제어 중 이용자가 화면 아무 곳이나 터치하거나 **[취소]** 버튼을 누르면, 접근성 제어 이벤트가 즉시 강제 종료됩니다.
